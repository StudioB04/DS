# StudioB04 Design System

`@studio_b04/ds` is the React component library and CSS token system shared by every StudioB04 website. It gives each project the same building blocks, the same visual language and the same level of accessibility, so teams can focus on their product instead of rebuilding buttons.

Every component:

- extends the props of its HTML element and accepts a `className`;
- follows the [W3C ARIA Authoring Practices](https://www.w3.org/WAI/ARIA/apg/) and is tested with axe;
- only uses design tokens, so it follows the theme and can be customised with CSS custom properties;
- respects the user's reduced motion preference.

## Getting started

### 1. Install

React 19 and React DOM 19 are peer dependencies.

```bash
npm install @studio_b04/ds
```

### 2. Load the styles

Import the tokens once, in your global CSS. The reset is optional but recommended.

```css
@import "@studio_b04/ds/reset";
@import "@studio_b04/ds/styles";
```

With Tailwind 4, add the theme after Tailwind to get the tokens as utilities:

```css
@import "tailwindcss";
@import "@studio_b04/ds/styles";
@import "@studio_b04/ds/tailwind-theme";
```

### 3. Use the components

Each component imports its own CSS, so there is nothing else to load.

```tsx
import { Alert, Button } from "@studio_b04/ds/uikit";

export default function Example() {
  return (
    <Alert title="Welcome" variant="brand">
      <Button label="Get started" variant="brand" iconEnd="arrow-right" />
    </Alert>
  );
}
```

Browse the **Components** section of the sidebar: every page shows the live component, its props and its usage notes.

### 4. Choose a theme

The light theme is the default, and the dark theme follows `prefers-color-scheme`. Set `data-ds-theme` on `<html>` to force one:

```tsx
document.documentElement.dataset.dsTheme = "dark";
```

### 5. Customise

Fonts and most component settings are CSS custom properties. Override them in your own CSS:

```css
:root {
  --ds-font-family-sans: "Inter";
}

.my-carousel {
  --ds-slider-gap: var(--ds-spacing-md);
}
```

### Conventions

- **Accessibility first:** follow the W3C pattern of the component, keep interactive targets at least 24 × 24 px, and start each test file with an axe test.
- **Tokens only:** use the semantic tokens (`--ds-text-*`, `--ds-bg-*`, `--ds-border-*`) and the scale tokens (`--ds-spacing-*`, `--ds-radius-*`, …), never raw values or palette colours.
- **CSS:** BEM classes (`.ds-name`, `.ds-name__element`, `.ds-name--prop-value`), native nesting, logical properties, and modifiers that only set local custom properties.
- **TypeScript:** `import type` for types, no `any`, defaults in the props destructuring, `className` and the remaining props forwarded to the root element.
- **Stories:** a `defaultArgs` object that every story extends, and an English description in `parameters.docs.description.component`. The documentation pages are generated by `autodocs`.
- **Tests:** cover every prop, variant and state; aim for 100 % coverage.

### Commit and release

A pre-commit hook runs the build, the linter, Prettier and the tests: all of them must pass. Open a pull request on `main`; Storybook is published automatically once it is merged.

Releases are made with the **Release** GitHub Actions workflow (patch, minor or major, with a dry-run option). Never change the version in `package.json` by hand.
